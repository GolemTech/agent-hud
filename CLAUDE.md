# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Agent HUD is a Claude Code plugin ("mod"): a hooks module that draws a live sidebar (Session, Context, MCP, Subagents, Todo, Gentle AI) and a band above the prompt. User-facing behavior and data sources are documented in `README.md`; keep both in sync when behavior changes.

## Commands

```sh
claude --plugin-dir .                            # session with the plugin loaded from this folder (also writes .claude-plugin/types/)
claude plugin test .                             # runs every hooks/*.test.ts(x); there is no per-test or per-file filter
claude plugin validate .                         # manifest, marketplace and hooks module; lists hooks, $ calls, gating hooks
npx -y -p typescript@5.6.3 tsc -p . --noEmit     # type-check; needs .claude-plugin/types/ (git-ignored, written by a --plugin-dir load)
```

`validate` does not type-check: run `tsc` too, it catches errors `validate` passes. The only expected `validate` warning is that a root `CLAUDE.md` is not shipped as plugin context; that is intended (this file is for developers, not for users of the plugin).

CI (`.github/workflows/ci.yml`) runs `test`, `validate`, gitleaks and semgrep; `tsc` is not in CI because it needs the generated types, so run it locally.

API reference: `.claude-plugin/types/claude-code/index.d.ts` (~15k lines). Grep for the event or noun (`'turn.step'`, `PaneOpenArgs`, `ButtonProps`) and read the doc comment; it is the source of truth over memory.

## Architecture

Everything runs from `hooks/register.tsx`. The top of the file is pure, exported helpers (formatting, merging, ordering, parsing), unit-tested in `hooks/timing.test.ts`. `register` at the bottom wires the hooks.

- **Poller drives redraws.** `session.start` registers `/hud`, opens the pane and starts `$.clock.every(1000, tick)`. Each tick refreshes slow caches on their own cadence (session title every 2 ticks, git branch and `git diff --shortstat HEAD` change counts 5, output style from settings 30, account 60, UTC offset 600), then writes the `rows` atom. Writing an atom redraws every render that read it, which is why both the Pane and the AbovePrompt band read `rows` first: that is their refresh signal.
- **State lives in two places.** `$.state` atoms (`rows`, `collapsed`, `todos`, `private`, `scroll`, `theme`, `picker`, `preview`, `pickerScroll`, `lists`, `mcpFilter`, `settingsOpen`, `hiddenSections`, `meterStyle`, declared in `types/index.d.ts` under `PluginState['agent-hud']`) survive reloads. Module-level variables (`seen` timing map, `loopModel`, the caches, the `cleared*` sets) reset on every reload; that is accepted.
- **Event-sourced data.** `agent.spawn` stamps a subagent's real start time and model; `turn.step` records model and effort per loop (`agentId`, or `'main'`) and, from its result's own usage, a subagent's context size (never `turn.complete`'s usage: it sums every request of the turn and runs into millions; the kit could not be made to answer `turn.step` in a test, so that path is covered by `ctxTokens` alone; its bookkeeping before and after `yield* next(e)` is in try/catch, so a failure there never changes or fails the request's result); `prompt.compose` records the output style's name (a pure observer, forwards `next(e)` untouched; its input names no loop and `PromptComposeInput` has no field that tells the main loop from a subagent, so only a named style updates it and a style-less compose, like a subagent's, is ignored; a change in the polled `outputStyle` setting resets it, which is how a switch back to the default shows); `tool.call` on `TodoWrite` / `TaskCreate` / `TaskUpdate` mirrors the main loop's todos (`!e.agentId`). `$.agent.list()` gives live status only, and finished agents drop out of it, so `mergeRows` keeps them as history until "clear done".
- **Two surfaces.** The `Pane` (id `hud`) and the `AbovePrompt` band. The band shows only when `isSidebarShown($.ui.panes())` is false; it asks the engine instead of tracking opens and closes (see gotchas).
- **Gentle AI section.** `hooks/gentle.ts` holds its pure parsers, the action table (`actionSpec`: confirmation text, constant argv, env, result toast) and types, unit-tested in `hooks/gentle.test.ts` with the section's wiring tests. Everything that calls `$` (`detectGentle`, `runAction`, `fillPrompt`, `refreshGentle`) lives in `register.tsx`. Detection runs at session start, every 300 ticks, on `↻` and after an action, not awaited by the tick; a periodic or `↻` run joins one under way unless it started `GENTLE_JOIN_DEADLINE_MS` ago (stuck), an action's run starts fresh, and a generation number drops an older run's result. Command buttons run with `ACTION_TIMEOUT_MS`; a failure (exit code, rejection, unreadable cwd) is a `failed (...)` toast. Each probe is guarded on its own and leaves its field unknown when it fails. Command buttons go through `$.ui.ask` ('Run it' / 'Cancel', a rejection is a cancel) before `$.process.run`; prompt buttons only `$.prompt.fill` (`replace`), never submit.
- **Responsive layout.** `hooks/layout.ts` holds the pure sizing helpers, unit-tested in `hooks/layout.test.ts` with renders of the Pane at several widths and heights. The Pane sizes itself with `layoutFor(e.props.bodyColumns, e.props.scroll?.bodyRows ?? e.viewport?.rows)`: drawable columns (body less `paddingX`), meter `barWidth` (the cells of a track of `METER_GLYPH[meterStyle]`, `━` by default or `▬`, split by `barCells`), and the `compact` subagent tally. Rules: in a row of a label and what follows it, the label sits in a `flexShrink={0}` Box and the row has `flexWrap="wrap"`, so buttons and values go below instead of squeezing the label into one letter per line; anything else in such a row only holds truncating Text. Sticky header and footer: outside an inline frame and with `scroll.bodyRows` known, the Pane is drawn at exactly `bodyRows` (header `HEADER_ROWS`, a clipped `overflow="hidden"` viewport of `viewportRowsFor(...)` rows, footer `FOOTER_ROWS`), so the engine has nothing to scroll; the `ui.scroll` hook (an observer, forwards `next(e)`) moves the `scroll` atom by `e.by`, clamped to `maxScrollOffset(contentRows, viewportRows)` (overflow plus `SCROLL_BOTTOM_MARGIN`), and the sections Box is shifted by `marginTop={-offset}`. The render clamps the offset too (a collapsed section, a resize) and records the max in `scrollMax` for the hook; `session.start` resets it to 0. `contentRows` is counted from one keyed list, `sectionItems: Record<SectionId, { rows, node }>` (`satisfies` makes a section without both a compile error): each item holds every row its section draws (`flowRows` for wrap rows, `textRows` for wrapping text, every subagent card) and its tree; the tree and the count both read `visibleSections(hidden)`, only the first drawn section has no margin row (`margin(id)`), and with none drawn the count is `textRows(ALL_HIDDEN_TEXT.length, W)`. Change a section's rows and node together. The header names the project (`projectName` of the repository root the branch poll saw, else the cwd; `project` in the view, `…` under `maskView`). The Gentle AI section is one grid built as data (`gentleGrid` in `gentle.ts`): headings at `HEADING_INDENT`, items at `ITEM_INDENT` as label · value · detail/buttons, label and value columns padded to the section's widest (`gridFor`); both the tree and `gentleRows` read that one list.
- **Demo mode.** `hooks/demo.ts` provides the sample session behind `/hud-demo`, used for README recordings; both surfaces render from one view object, live or demo, and demo data never reaches `$.state`.
- **Themes.** `hooks/themes.ts` holds the pure palettes (`default`, twenty dark presets, then ten light ones in `LIGHT_THEMES` / `isLight`; 31 in all), the resolver and the `/hud-theme` argument parser, unit-tested in `hooks/themes.test.ts`; the command, the `theme` atom and its `$.store` copy (loaded at `session.start`) live in `register.tsx`, with wiring tests in `hooks/theme-command.test.ts`. `/hud-theme` without a name sets the `picker` atom, resets the scroll to 0 and opens the HUD's own Pane (`id: 'hud'`, same title) with `focus`, all through `startPicker($)`, which also closes the settings block and is shared with its `[change]`; a second pane would be seated as a dock tab hiding the sidebar, which defeats the live preview. An open answering the person's command is placed at any width, but its `focus` is refused while the command still runs (it is granted only over an empty composer), so `$.clock.after(PICKER_FOCUS_RETRY_MS)` opens it again to ask for the keys, unless the picker was already answered. No `closeOnEscape`: Escape only returns the keys. The picker is a block at the top of the sections (one `plain` Button per theme keyed `theme:<name>`, the saved one `autoFocus`, a plain `light` Text (`LIGHT_SEPARATOR`) right before the first light theme, and `theme-cancel`), counted in `contentRows` by `pickerRows(hasKeys)`, separator included; the separator is no Button, so `PICKER_ORDER` and the carousel ring step from the last dark theme straight to the first light one; the sections stay drawn below it. Fixed window: the rows (`PICKER_LIST`, null for the separator, which counts as a row) draw inside an `overflow="hidden"` Box of `PICKER_WINDOW = 10` rows shifted by `marginTop={-offset}`, every theme Button still drawn (clipped ones stay in the ring), with an indicator Text above and below (`moreText`, blank `' '` when nothing is hidden on that side) always drawn, so `pickerRows` = `pickerListRows(...)` (window + 2, or the whole list when it fits, then no window and no indicators) + hints + Cancel + margin never changes with the offset. The offset is the `pickerScroll` atom: `startPicker` sets it so the saved theme is in view (`scrollToRow(0, pickerRowOf(saved), ...)`), `closePicker` (also run at `session.start`) resets it to 0, the `ui.focus` hook moves it with `scrollToRow` (the least move that shows the focused theme, so a carousel wrap lands at that end), and while the picker is open `ui.scroll` moves it by `e.by`, clamped by `clampPickerScroll` to `[0, rows - PICKER_WINDOW]`, instead of the main `scroll` atom. The window math is the shared list window (`hooks/windows.ts`) over unit heights, wrapped in `themes.ts` and unit-tested in `themes.test.ts`. The `ui.focus` hook on `hud` (an observer, forwards `next(e)`) writes the `preview` atom from the focused key (`themeFromKey`; anything else, including an absent element, clears it); both surfaces draw `shownTheme(theme, preview)`, and the Pane drops the preview while `e.props.isFocused` is false: the types raise no event when the keys leave a pane (no blur; Escape just hands them back), so a render-only rule reverts the colors without a state write, and a second hint names `ctrl+x tab` or a click. A press saves through `finishPicker`, Cancel only closes the block; the Pane stays open; `session.start` clears both atoms. Wiring tests in `hooks/theme-picker.test.ts` raise the move with the test `$.ui.focus({ component, requestId, plugin, element, origin })` (bottom `ui.focus` answers `{}`), redraw with `isFocused: false` for the lost-keys case, and read the HUD's accent from the header's `settings` Button, since the picker rows draw every theme's accent as a swatch.
- **Picker carousel.** Focus events carry no direction (`UiFocusOrigin` is only `person` or `plugin`), so the `ui.focus` hook infers a wrap from the previous element (`pickerLastFocus`, module-level, reset when the picker opens or closes and at `session.start`): the pure `wrapFocus(prev, next, PICKER_ORDER)` (`hooks/themes.ts`) turns a person's step from the last theme onto the element right after it (Cancel) into the first theme, and from the first theme onto the element right before it (the header's `⋮`, `SETTINGS_KEY`, its only Button; `pickerOrder(SETTINGS_KEY)` is the ring order the render draws, so nothing may be drawn between the header and the picker) into the last, via `next({ ...e, element })`. Only adjacent steps are rewritten; jumps and `plugin` moves pass untouched, and any failure forwards `next(e)`. Cancel is off the keyboard ring's path (it sits after the last theme), so it has `hotkey: 'c'`. A click on Cancel right after resting on the last theme has its focus move redirected to the first theme, but the types raise `ui.press` separately with the clicked Button's own key, nothing ties the press to where the ring lands, so the click still cancels.
- **Settings block.** `hooks/settings.ts` holds the pure pieces (`SectionId`, the `⋮` constants with `SETTINGS_BUTTON_CELLS = 7`, labels, `settingsRows`), unit-tested with the wiring in `hooks/settings.test.ts`. The header's only Button is `⋮` (`SETTINGS_KEY`); the `►` hide button is gone because the engine's close mark on the frame (and `ctrl+x x`) already closes the Pane. `toggleSettings` flips the `settingsOpen` atom (not stored; `session.start` clears it), resets the scroll to 0 and closes a picker without saving; `[change]` calls `startPicker`. The block is drawn first in the sections, never with the picker, and counted by `settingsRows(W, theme)`: keep the two in step. The button is `'   ⋮   '`: three spaces each side widen the click target to a fixed 7 cells (not the whole header bar), and U+22EE is a monochrome text glyph (East Asian Width Neutral, one cell everywhere) painted in the theme's colors, so `SETTINGS_BUTTON_CELLS = 7` is exact. The block also holds `hiddenSections` (atom plus `$.store` key `hiddenSections`, loaded through `parseHidden` at `session.start`; missing or invalid is none) and one `plain` check per section (`sectionKey(id)`, `checkText`, same width checked or not), one per row in `SECTION_IDS` order. Above the checks, the `Meters` rows hold the meter glyph: `meterStyle` (atom plus `$.store` key `meterStyle`, loaded through `parseMeterStyle` at `session.start`; missing or invalid is `line`), `METER_GLYPH` (`line` `━`, the default; `block` `▬`), one `plain` choice per row in `METER_STYLES` order (`meterKey(style)`, `meterText`, same width chosen or not, `Meters` on the first row); `setMeterStyle` applies the choice at once and a failed `$.store.set` still applies it for the session. Both meters in the Context section draw the chosen glyph, live or demo (a view choice, like the MCP filter); the band draws no meter. Every row of the block is a label cell (`SETTINGS_LABEL_CELLS`: indent, `Sections` and a two-cell gap; `Sections` on the first check row, blank on the rest) and a value cell of exactly the rest of the line (`settingsValueCells(W)`), both `flexShrink={0}` in a `flexWrap` row, so the row never wraps and the Theme value, every meter choice and every check start in one column; only the Theme value (name and `[change]`) wraps inside its cell, with `columnGap={1}`, never `gap` (on a wrapping row its row gap is a blank row between the lines, which the count misses); `[close]` is indented like the labels. `toggleSection` never touches `collapsed`, and a failed `$.store.set` still applies the hide for the current session. The band builds its line from `summaryLine(..., hidden)` (`summaryParts`) and draws no summary `Text` when it is empty. Hiding is view-only: polls, detection and event bookkeeping keep running.
- **List windows.** `hooks/windows.ts` holds the pure list-window math (unit-tested in `hooks/windows.test.ts`), shared with the picker (`clampPickerScroll`, `scrollToRow`, `pickerMore`, `pickerListRows` and `moreText` in `themes.ts` are the same helpers over unit heights). A list is its items' heights (`CARD_ROWS` or `CARD_ROWS - 1` per card, `textRows(4 + content, W)` per todo); past `SUBAGENT_WINDOW = 12` / `TODO_WINDOW = 8` rows it draws as an indicator Text, an `overflow="hidden"` Box of exactly the window's height holding only the whole items from `first` (`windowAt`: an item is never cut; the rest of the window stays blank; only an item taller than the window alone is clipped), and an indicator Text, both always drawn (`moreText || ' '`), so the section counts `windowRows(...)` (window + 2) whatever the offset. A list that fits draws its items exactly as before, no wrapper. Offsets are in items, the indicators count items (a partly fitting item is hidden below). The `lists` atom holds `{ first, paused, pausedAt }` per list (`ListScroll`; `session.start` resets both to `LIST_TOP`). Follow is render-only: `shownFirst` keeps the active item (first `in_progress` todo, first `running` card; cards are drawn running first, so that is the top) in view with the least move unless `paused` and `pausedAt` is still the active id, so no atom is written to follow. The sticky render records `listsDrawn` (module-level, like `scrollMax`; null in the plain flow): each windowed list's span in body rows (`HEADER_ROWS` + the block rows + the sections and margin rows before it + its header rows and the Subagents tally − the clamped `scroll` offset), the first item it showed, its heights and active id. `ui.scroll` (after the picker branch) hit-tests `e.pointer.row` with `listAt(spans, row, HEADER_ROWS, viewportRows)` (rows outside the viewport never match); over a list it writes `wheelList(shown, e.by, ...)` (one item per row of `by`, the follow paused on the active id it saw) and forwards `next(e)` without moving `scroll`. No pointer (scroll keys, `$.ui.scroll`) or another row moves the Pane as before. The test kit draws lazily: a test must `pane.drawn()` after changing the lists and before raising a wheel, as the engine has drawn by the time a person wheels. Wiring tests in `hooks/scroll.test.ts` hide every other section, so the list's rows sit right under the header.
- **Theme background.** Each preset carries an optional `background` (its editor background); `default` has none. Light presets also carry `foreground` (their editor text color): `fg(t)` (`themes.ts`) adds `color={t.foreground}` only when set, and every Text with no role color in the Pane takes it (`{...fg(t)}`, or `t.foreground` where a Gentle AI mark has no tone); `default` and the dark presets have none, so their trees are byte-identical. `themes.test.ts` checks every role but `subtle` at 3:1 or more on the background and the foreground at 4.5:1; where an upstream color fell short, the comment above `THEMES` names the shade used instead. The Pane's root Box (plain flow, sticky layout and the version notice) and the band's root take `{...fill(t)}`, which adds `backgroundColor` only when the theme has one, so `default` draws byte-identical trees on the terminal's background. The types document neither how a Box background fills empty cells nor whether nested Text inherits it; the sticky layout already draws the Pane at `bodyRows`, but whether padding cells, blank rows and the space right of short lines are painted is only confirmed in a real session. Inverse elements (header band, section titles) swap to the accent over that background.
- **MCP filter.** `hooks/mcp.ts` holds the pure `filterServers(servers, mode)` (`active` keeps connected servers and counts the hidden ones), the empty/hidden lines and `mcpBodyRows` for `contentRows`, unit- and wiring-tested in `hooks/mcp.test.ts`. The `mcpFilter` atom (`all` | `active`) and its `$.store` copy (key `mcpFilter`, loaded at `session.start`, missing or unknown is `all`) live in `register.tsx`; the `mcp-filter-active` / `mcp-filter-all` Buttons in the MCP header (shown while the section is expanded, counted in its header `flowRows`) call `setMcpFilter`. The buttons work in demo mode too: the filter is a view choice, not demo data. No hotkeys (they would clash across the Pane).
- **Version gate.** `hooks/version.ts` holds `MIN_CLAUDE_CODE_VERSION` and the pure `isSupportedVersion` (unit-tested in `hooks/version.test.ts`, with wiring tests). The manifest has no minimum-version field, so `session.start` checks `$.session.version()`: below the minimum it toasts, registers only `/hud` and returns before the poller starts, and both surfaces draw only the notice (`unsupportedNotice`); an unknown or unreadable version runs normally.
- **Privacy mode.** `/hud-private` flips the `private` atom; `liveView` applies the pure `maskView` (identity fields only) when it is set, so both surfaces read masked data from one place. Demo mode wins over it. The `🔒` mark is drawn in the header band (`🔒 📂 …`), not in a section, so it shows whatever is hidden.
- **Fragile inputs** are read from Claude Code internals with a fallback, never trusted: `~/.claude/projects/<projectDir(root)>/<sessionId>/custom-title.json` (session title), `~/.claude.json` `oauthAccount` (account; only email user and organization are kept, never the email domain), and the `outputStyle` setting from `<root>/.claude/settings.local.json` > `<root>/.claude/settings.json` > `~/.claude/settings.json` (`outputStyleFrom`). The `~/.claude` files move under `CLAUDE_CONFIG_DIR` when it is set (`claudePaths`). External strings pass through `clean` (`hooks/text.ts`, control characters stripped) where they enter.

## Mods API gotchas (all hit in practice)

- Every `<Button>` needs `onPress`; without it the render hook throws and the whole Pane draws blank. State changes from a button go through `update($, atom, fn)` inside `onPress`.
- Call `$` at the call site: `$.process.run(...)` works, passing `$.process.run` as a value is refused by `validate`.
- `$` is followed only into functions declared in the same file, never across an import: a helper in `gentle.ts` that takes `$` makes the whole module fail to load ("$ is passed to ..., imported from ..."). Keep `$`-calling code in `register.tsx` and only pure code in other modules.
- Never run gga for detection: every gga command except `run` checks GitHub for updates (curl; `CURL_CMD=false` turns it off), and `gga config` / `gga version` source the repository's `.gga`, which executes it. Read the hook files and `.gga` as text instead (`parseGgaConfig`).
- `brew outdated --json=v2` exits 1 when something is outdated: parse stdout, do not gate on `exitCode`. Run brew with `HOMEBREW_NO_AUTO_UPDATE=1` so it reads only the local tap.
- A plugin's own `$.ui.open` / `$.ui.close` is not seen by its own `ui.open` / `ui.close` hooks (origin `plugin`), and a state write from a closing pane's button can be lost when the pane unmounts. Derive visibility from `$.ui.panes()` instead of tracking it.
- "plugin panel hidden · ctrl+x ctrl+a or click to show" is the engine collapsing the AbovePrompt band, not a missing band. A plugin cannot expand it.
- Size the Pane from `e.props.bodyColumns` (the body's own cells) and `e.props.scroll.bodyRows`, not `e.viewport`: the viewport is the whole conversation's width and the surface's rows, and a height-only change of the viewport re-draws nothing. The Pane's props change on a resize, which re-runs `ui.render` (and the poller's `rows` write redraws every second anyway), so no refresh signal is needed. The test kit draws trees, not text: `pane.redraw(props)` re-renders at another size.
- `$.ui.open({ columns })` is a request: a dock width the person set wins, so a narrow "rail" is not reliable.
- `turn.step` is a streaming event: the hook must be `async function*` ending in `return yield* next(e)`, and must not await `$` before forwarding (it would delay every response).
- `$.process.run` resolves on any exit code (it rejects only when the command cannot start or outlasts `timeoutMs`, default 30 s): check `exitCode`, as the `git diff` refresh does for a repository with no `HEAD`. Every read-only run passes `CMD_TIMEOUT_MS` or `BREW_TIMEOUT_MS` (`gentle.ts`).
- Claude Code runs every git with `core.hooksPath` forced to `/dev/null` (also through `GIT_CONFIG_*`), so `git rev-parse --git-path hooks` answers `/dev/null`. Find a repo's hooks folder with `--git-common-dir` plus `git config --file <common>/config --get core.hooksPath` (`hooksDir` in `gentle.ts`).
- A lambda parameter named `on` inside `register` makes the hooks module fail to load (it shadows the `on` the loader follows); use another name.
- Gating hooks (`agent.spawn`, `tool.call`) are observers here: keep `.catch((_$, e, next) => next(e))` so a failure never blocks the call.
- Use `$.clock.now()`, not `Date.now()`, so the clock is mockable; and get the time zone from the host (`date +%z`), not from `Date`, whose zone may differ from the user's.
- Colors go through theme roles (`accent`, `subtle`, `success`, `warning`, `error`; `hooks/themes.ts`), never a literal: each render reads the palette once (`activePalette`: the `preview`, else the saved `theme`) and writes `color={t.accent}`. The `default` theme maps the roles to Claude Code theme keys, so it follows `/theme`; the `/hud-theme` presets are raw `#rrggbb` colors, each on its own background (the light ones with their own `foreground`). A Text with no role color still takes `{...fg(t)}`, never a bare `<Text>`. Name no other local `t` inside a render (it shadows the palette).

## Tests (`claude-code/testing` kit)

- Prefer pure helpers tested directly; engine tests are for wiring. `hooks/band.test.ts` is the reference: it mounts the Pane, presses a button by `key`, and asserts the band's `drawn()` tree.
- The test's `on(...)` hooks are the engine's bottom. `$` calls are answered as `{ value }`, lifecycle events raw (`session.start` → `{ cwd }`), and `ui.render` must return a tree element, e.g. `h(Box, {})` from `$.ui.resolve(e)`.
- Anything the code under test calls needs a bottom answer, or the hook is skipped with "no implementation".
- A test cannot read another plugin's `$.state` (host rule); assert through rendered output instead. The test `$` has no `$.ui.close`; reach it by pressing the plugin's own button.
- An engine event a test raises from its own `$` (e.g. `$.prompt.compose(input)`) runs every plugin's hook; its bottom answers raw (`on('prompt.compose', () => ({ sections: [] }))`). `hooks/session.test.ts` does this.
- The test `$` has no `$.ui.ask`; the plugin's own call runs the `AskUserQuestion` tool, so a test answers it with `on('tool.call', { tool: 'AskUserQuestion' }, ...)` returning `{ result: { answers: { [question]: label } } }`, and throws to simulate a dismissed dialog. `prompt.fill` and `ui.toast` need bottom answers too. `hooks/gentle.test.ts` does this.
- `mock.clock(on)` controls `$.clock.now()` / `every`; advance it instead of sleeping.
- Fixtures use reserved names only (`example.com`, `.test`, `/home/myuser`): a local identity guard blocks commits with real-looking data.
